# Auditoría de resiliencia y recuperación

| Flujo                    | Timeout                                                                             | Reintento                                                                                             | Idempotencia/cuarentena                                                         | Estado de error y recuperación                                           | Resultado                                        |
| ------------------------ | ----------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------ |
| LLM/agente               | El transporte conserva la configuración del SDK y aborta en el límite del proveedor | Backoff exponencial con jitter, hasta cuatro reintentos sobre respuestas no exitosas o errores de red | No ejecuta acciones externas; la salida inválida activa fallback seguro         | Error final conserva el manejo del router y registra métrica de fallback | Implementado                                     |
| Ingesta de catálogo      | HEAD de URL 5 s; fuente 15 s                                                        | La ejecución se puede reintentar sin duplicar por clave estable                                       | Upsert por fuente y URL canónica; candidatos inválidos van a cuarentena         | Estados `pending_review`, `quarantined` y razón visible para revisión    | Implementado                                     |
| Callback catalog refresh | Límite de ejecución de Heartbeat: 2 min                                             | El proveedor reintenta respuestas 5xx/429                                                             | Busca job por `taskUid`; ejecuciones se registran como succeeded/failed/skipped | Error JSON, `automation_runs` y logging estructurado                     | Implementado con activación productiva pendiente |
| Callback growth report   | Límite de ejecución de Heartbeat: 2 min                                             | El proveedor reintenta respuestas 5xx/429                                                             | Snapshot persistente y job localizado por `taskUid`                             | Error JSON y run fallido persistido cuando la DB lo permite              | Implementado con activación productiva pendiente |
| Catálogo público         | React Query expone error y retry en la UI                                           | Reconsulta manual desde la interfaz                                                                   | Lectura sin mutación                                                            | Empty, loading, error y success diferenciados                            | Implementado                                     |
| Recursos multimedia      | La lista y el reproductor nativo dependen de la red del navegador                   | Reintento de consulta disponible                                                                      | Bytes fuera de DB; metadata separada                                            | Error y vacío visibles                                                   | Implementado                                     |

Quedan fuera de esta conclusión la disponibilidad de proveedores externos, la persistencia de rate limiting entre instancias Autoscale y la activación de jobs productivos antes de desplegar. Esas dependencias se mantienen explícitas en `docs/secrets.md` y `todo.md`.
